# FLIGHT_SOFTWARE — PGK SIH26098 reference flight software

**Rev 1.0 (2026-08-31)** — companion to `04_GNC_METHODOLOGY.md` (Rev E), evidence in
`out_sim/RESULTS_FSW.md` (generated by `cosim/run_cosim.py`). This document maps the
Python reference package `cleansheet/flight_sw/` onto the STM32G474 deployment and
records measured budgets + the C-port checklist.

## 1. What this package is

A **deterministic Python reference flight-software implementation** of the Rev E GNC
methodology: module boundaries, task rates and interfaces mirror the on-board
deployment above the motor FOC (scheduler → sensors → navigation → guidance → roll
control → mode state machine). It is verified by co-simulation against the Rev E 3DOF
truth model with paired Monte Carlo (same dispersion draws, verified draw-count
parity).

Hard boundary rule (enforced structurally): **FSW code never imports truth/sim
internals.** Only `cosim/` imports `scripts/sim_gnc_check.py` (truth dynamics + sensor
synthesis). FSW sees the world exclusively through `fsw/sensors.py`.

## 3. Module → ISR / peripheral map (vs report §4.5, §7)

| FSW module | On-board home | Trigger / ISR | Peripherals |
|---|---|---|---|
| `timebase.Scheduler` | SysTick 100 Hz base | SysTick ISR | — (tick counter) |
| `ctrl` (pattern + servo cmd) | control task | 400 Hz timer ISR (deployment) | servo/rotor motor bridge via FOC (15 kHz HRTIM, out of scope), collar↔bell angle sensor (commutation monitor) |
| `sensors` + roll predict (40 Hz) | sensor ISR | 40 Hz (IMU decimated from 200 Hz) | ICM-45686 gyro (SPI, 4 k°/s sat), averaged accel (body frame) |
| `nav.NavEKF.predict` (100 Hz deployment) | GNC task | 100 Hz SysTick slot | — |
| `nav.deliver_fix` (GNSS update) | GNC task, event-driven | UART DMA complete → fix queue | NavIC L1/L5 GNSS receiver (1 Hz, 100 ms latency, time-tagged) |
| `nav` anchor + SlowFit (40 Hz) | GNC task | 40 Hz | accel average buffers |
| `guide` IPP + laws (1 Hz) | GNC task | 1 Hz | — |
| `modes` ladder + lock deadline | GNC task (every tick) | — | GNSS lock status line |
| `dynamics` q-profile/q70 | pre-flight tables | loaded at init | — |

Deployment task rates: **servo 400 Hz, sensors/roll 40 Hz, EKF predict 100 Hz, GNSS 1 Hz,
guidance 1 Hz** — fixed rates, no dynamic allocation, no dynamic priorities.
Co-sim cadence: every FSW task offered once per truth step (DT_TRUTH = 0.025 s) and
the EKF predict runs at the truth cadence — this replicates sim_gnc_revE's own
documented simplification and is what makes the paired MC bit-faithful; the
deployment rates above are exercised in `tests/test_timebase.py`.

## 4. The control↔navigation interface (the architecture rule)

Control and navigation are coupled **through the commanded pattern**: the drag-vector
anchor needs pattern-change + settle notifications (a window straddling a servo flip
is slew-poisoned). This is an explicit published interface, not hidden state:

```
ctrl task ──publish("pattern_change", {t, az})──▶ EventBus ──▶ nav.on_pattern_change()
                                                                    └─ window.flush()
```

The servo loop nulls `wrap_pi(pattern_azimuth(t) − psi_hat)` — computable entirely
from FSW quantities (commanded schedule + roll estimate); the truth integrator in the
co-sim applies the same time-optimal rate command with the rate/alpha caps
(6.28 rad/s / 55 rad/s², discretization-safe near-target cap).

## 5. Measured budgets (Python host reference)

`cosim/run_cosim.py --budget` (perf_counter over 2 full deterministic shots; the
scheduler offers every task once per truth step, so "calls/shot" reflects the co-sim
cadence — on-board counts are rate × flight time; the 1 Hz guidance tick self-gates):

| Task | mean/call (µs) | max/call (µs) | role |
|---|---|---|---|
| EKF predict (12×12 F/P) | 23.0 | 139 | 40 Hz co-sim / 100 Hz deployment |
| guidance tick (IPP ~600 RK4 steps + law) | 10.7 (mostly gate) | 1704 | 1 Hz — the worst-tick driver |
| slow fit (model twin) | 6.9 | 57 | 40 Hz |
| ctrl (pattern refresh + wobble) | 3.5 | 21 | 40–400 Hz |
| GNSS delivery (Joseph update) | 2.5 | 181 | 1 Hz |
| anchor solve (windows) | 0.4 | 41 | ~1 Hz effective |
| sensor entry (gyro + accel settle) | 18.1 | 83 | 40 Hz |

Host note: CPython on a laptop is the reference interpreter; the STM32G474 budget in
`04_GNC_METHODOLOGY.md` §7 (<0.5 ms worst 1 Hz tick, ~2 kFLOPs EKF predict, ~9 kFLOPs
IPP) remains the C-target sizing — the measured Python numbers above bound the
algorithmic structure (no hidden O(N) paths; the IPP dominates the 1 Hz tick exactly
as budgeted). RAM < 5 KB (state 96 B, P 1.15 KB, roll states, anchor buffers 32×6
scalars, GNSS queue 1 fix), flash < 20 KB — unchanged from methodology §7.

## 6. C-port checklist

- [x] no dynamic allocation (fixed buffers: window 32 samples, GNSS queue depth 1,
      12-state EKF, 3-state roll EKF) — verify `malloc` absence in C port
- [x] fixed task rates, static registration (Scheduler is registration-static)
- [x] event interface = single callback registration (pattern_change → flush)
- [x] all constants in one module (config.py → config.h); units on every line
- [x] angle wrapping single definition (wrap_pi) — port once, reuse
- [ ] float→fixed-point candidates: EKF P-matrix (0.16–100 range, Joseph form needs
      headroom → Q15.16 or float w/ FPU), anchor accumulation (float, 32-sample sum),
      IPP integrator (float), duty/azimuth (Q15 fixed suffices)
- [ ] replace numpy linear algebra in `update_gnss` (6×12 Joseph) with hand-rolled
      6×6 reduced form (H is a selection matrix — exploit sparsity)
- [ ] ISR safety: GNSS queue single-producer/single-consumer (UART DMA ISR writes,
      GNC task reads) — double-buffer, no locks needed at depth 1
- [ ] watchdog: guidance-tick deadline monitor (worst tick = IPP ~1704 µs Python;
      C target < 0.5 ms per methodology §7)
- [ ] out of scope (next rungs): motor FOC internals (15 kHz ISR time budget),
      embedded C port itself, 6DOF truth upgrade, GNSS receiver hardware details,
      MC ≥ 1000 (report §10.1)
